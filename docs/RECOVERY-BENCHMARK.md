# 冷启动恢复基准

记录不同优化阶段下，路由器重启后各服务的恢复时间。

**测试方法**：`/sbin/reboot` 后用 `curl` 轮询各端点，记录首次返回成功的时间。

## 测试环境

| 项目 | 规格 |
|---|---|
| 型号 | RT-AC51U-GPIO-12-ji2-128M（极路由2） |
| SoC | MT7620A 单核 580MHz |
| 内存 | 128MB |
| 固件 | Padavan 3.4.3.9-099_26-03-1 |
| 存储 | U 盘 58GB（ext4，2GB + 56GB 两分区） |

## 优化对比

| 版本 | 网站 | 代理 | 面板 |
|---|---|---|---|
| v1（依赖固件） | ~90s | ~180s | ❌ |
| v2（配置持久化） | 87s | 134s | ❌ |
| **v3（模板 + 校验）** | **41s** | **53s** | **54s** |

**相对 v1**：代理恢复快 3.4 倍，面板从不可用变为 54 秒可用。

---

## 影响恢复时间的因素

| 因素 | 影响 | 说明 |
|---|---|---|
| U 盘供电 | **决定性** | 极2 USB 口弱，USB 3.0 盘可能启动失败，需物理拔插 |
| 固件 automount 冲突 | 大 | 会把分区挂到 `/opt`，必须先清理 |
| clash 配置生成 | 大 | 下载订阅 + yq 改写，1-2 分钟 |
| GeoSite 加载 | 大 | 13.7 万条规则，87 秒 + 50MB 内存 |
| MMDB 下载 | 大 | GitHub 国内超时，直接 fatal |
| nginx 启动 | 小 | 秒级 |
| swap 启用 | 小 | 秒级 |

## 稳定性验证

连续 3 次重启，全部自动恢复：

| 次数 | 结果 | 备注 |
|---|---|---|
| 1 | ✅ | 发现 `/opt/app` 被清空问题 |
| 2 | ✅ | 发现配置被订阅覆盖问题 |
| 3 | ✅ | 全部正常，41-54 秒恢复 |

## 已知残留问题

**固件和我们的脚本会抢 clash 配置**

```
固件：写原始订阅 → yq 改写 → 生成配置
我们：检测配置 → 恢复模板
```

目前靠"检测到不对就恢复"兜底，下一轮（30 秒内）会修正。
彻底解决需要关掉固件的 `clash_enable`，但会失去固件的订阅管理（我们已有自己的更新脚本，理论上可行）。
